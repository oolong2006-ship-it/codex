# CLAUDE.md — Smart Attendance OS

> هذا الملف هو الميثاق الثابت للمشروع. يقرؤه الوكيل في بداية كل جلسة.
> أوامر التنفيذ موجودة في ملفات المراحل `prompts/phase-*.md`، والمواصفات الملزمة في `docs/specs.md`.
> عند أي تعارض: specs.md ← ثم هذا الملف ← ثم برومت المرحلة.

## 1. المنتج في سطرين

منصة SaaS متعددة العملاء للحضور والانصراف من جوال الموظف، دون أجهزة بصمة.
تتحقق من **ثلاثة أمور مستقلة**: الجهاز المعتمد، وموقع العمل، وسلامة الطلب. وكل قرار يصدر من الخادم ومعه أدلته.

- السوق الأول: السعودية. ثم الخليج.
- العميل التجريبي الأول: مجموعة مطاعم متعددة الفروع، بورديات ليلية وتنقل بين الفروع.
- الرسالة: «حضور موثوق. من هاتف الموظف. دون أجهزة إضافية.»

## 2. ما ليس من هذا المنتج (حتى يُعتمد خلاف ذلك)

- ليس نظام موارد بشرية كاملًا. الإجازات والرواتب **مراجع تُستورد وتُصدَّر** فقط.
- لا تتبع مستمر للموقع. الموقع يُقرأ **عند البصمة فقط**.
- لا تحقق بالوجه في الـ MVP. البيانات البيومترية حساسة وفق PDPL وتحتاج DPIA قبل أي تفعيل.
- لا أجهزة Kiosk ولا QR ثابت كوسيلة أساسية.
- لا قرارات تأديبية أو خصومات تلقائية. النظام يقترح والإنسان يعتمد.

## 3. القرارات المحسومة (لا تُغيَّر إلا بـ ADR معتمد)

| الطبقة | القرار | ملاحظة |
|---|---|---|
| Monorepo | pnpm + Turborepo، TypeScript في كل الطبقات | لغة واحدة لفريق صغير |
| Backend | NestJS، **Modular Monolith** | حدود وحدات صارمة، دون Microservices |
| Database | PostgreSQL 16 + PostGIS | migrations بـ SQL صريح أو Drizzle، وPrisma مستبعد بسبب PostGIS |
| Auth | يملكها الـ Backend (OIDC-ready، JWT قصير + refresh دوّار) | **لا** Supabase Auth. وإن استُخدم Supabase فهو Postgres مُدار فقط |
| Tenant isolation | `tenant_id` في كل جدول تشغيلي + Postgres RLS + فحص في طبقة الخدمة | الطبقتان معًا، لا إحداهما فقط |
| Mobile | React Native (Expo dev build) + وحدات أصلية لـ App Attest/DeviceCheck وPlay Integrity/Keystore | يجوز التحويل إلى Native كامل بـ ADR إذا تعذر أمن الوحدات الأصلية |
| Admin Web | Next.js (App Router) + TypeScript | لوحة الشركة + Super Admin في تطبيقين منفصلين |
| Jobs | BullMQ + Redis | |
| API | REST + OpenAPI 3.1، Webhooks موقّعة HMAC | |
| Hosting | منطقة داخل المملكة افتراضيًا | **تحقق** من توفرها لدى المزوّد قبل الاعتماد |
| i18n | العربية أولًا (RTL أصيل) + الإنجليزية | لا نصوص مضمّنة في الكود |

## 5. قواعد العمل غير القابلة للتفاوض

1. **الخادم هو صاحب القرار.** أي فحص في التطبيق هو تجربة مستخدم، لا أمن.
2. **وقت الخادم هو المرجع.** وقت الهاتف يُسجَّل كدليل فقط.
3. **أحداث البصمة append-only.** التصحيح ينشئ سجل تسوية، ولا يعدّل الحدث الأصلي أبدًا.
4. **لا أرقام نظامية في الكود.** ساعات العمل والسماح والعمل الإضافي ورمضان كلها سياسات بإصدار وتاريخ سريان.
5. **كل رفض له reason code** ورسالة عربية وإنجليزية مفهومة ومسار اعتراض.
6. **لا نجاح وهمي.** لا تعرض الواجهة نجاحًا قبل رد الخادم، ولا تُعلَن وظيفة مكتملة دون اختبار يعمل.
7. **لا بيانات وهمية خارج `seed` لبيئة التطوير.**
8. **أي خدمة خارجية** (سبل، الخرائط، الرسائل) تُبنى عبر Adapter مع Fake قابل للاختبار، ويُوسم تكاملها `Blocked` حتى يُختبر بمفاتيح حقيقية.
9. **لا تدّعِ** تكاملًا رسميًا أو دقة أو تفوقًا على منافس دون دليل مسجل.

## 6. معجم الحالات (يُستخدم في status.md وكل تقرير)

- `Complete`: منفّذ ومتصل بقاعدة البيانات ومغطى باختبارات ناجحة شُغّلت فعلًا.
- `Partial`: يعمل جزئيًا. اذكر الناقص.
- `Blocked`: يحتاج مفتاحًا أو اشتراكًا أو قرارًا بشريًا. اذكر المطلوب ومن يوفره.
- `Not Started`.

## 7. بوابة نهاية كل جلسة

قبل إنهاء أي جلسة:
1. شغّل `pnpm lint && pnpm typecheck && pnpm test` وانقل النتيجة الفعلية.
2. حدّث `docs/status.md`: جدول (البند | الحالة | الدليل: اسم اختبار أو ملف).
3. اذكر القرارات التي اتُّخذت دون ADR، والافتراضات الجديدة.
4. **توقف عند نهاية المرحلة** وانتظر الاعتماد البشري. لا تبدأ المرحلة التالية من تلقاء نفسك.
