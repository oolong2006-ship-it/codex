# المرحلة 0 — Discovery & Product Definition

اقرأ `CLAUDE.md` و`docs/specs.md` أولًا.

## الهدف
تحويل الفكرة إلى نطاق MVP محسوم بالأدلة. **لا شيفرة إنتاجية في هذه المرحلة.**

## المهام

### 1. مصفوفة المنافسين → `docs/research/competitor-matrix.csv` + `.md`
- المنافسون: Jisr، ZenHR، Bayzat، Palm HR، Jibble، Connecteam، Deputy، Zoho People، QuickBooks Time، Clockify، Workyard، Odoo Attendances، TECFY، PassMH، TimeMobi.
- **المصدر الوحيد المقبول:** صفحات المنافس الرسمية (ميزات، أسعار، مركز مساعدة، release notes). لكل صف رابط وتاريخ تحقق.
- الأعمدة: `competitor, feature_id, feature, how_it_works, plan, source_url, verified_on, hardware_needed(Y/N), category(CORE|PARITY|DIFF|ENTERPRISE|FUTURE|OUT), our_equivalent, acceptance_test`.
- نطاق الوظائف: الحضور، والموقع، والجهاز، والورديات، والاستراحات، والاستثناءات، وكشوف الوقت، وتصدير الرواتب، والتقارير. **لا** الإجازات الكاملة ولا التوظيف ولا التقييم.
- ميزة لم تجد لها مصدرًا لا تُكتب. وما لم يمكن التحقق منه يُكتب في قسم «غير مؤكد».
- تحقق من المقصود بمنصة «شؤون» ومن وجود تكامل لها قبل إدراجها.

### 2. المتطلبات السعودية → `docs/research/ksa-requirements.md`
لكل بند: المصدر الرسمي، وتاريخ التحقق، و**هل هو سياسة قابلة للضبط أم قيد ثابت**:
- نظام العمل: ساعات العمل اليومية والأسبوعية، ورمضان، والراحة، والعمل الإضافي، والسجلات المطلوبة.
- PDPL: الموقع والبيومتري، ومدة الاحتفاظ، وحقوق صاحب البيانات، ونقل البيانات خارج المملكة.
- واجهات سبل للعنوان الوطني: المتاح، وشروط الاستخدام التجاري، والتكلفة.
- صيغة ملفات حماية الأجور / مُدد للتصدير.
- مناطق الاستضافة المتاحة داخل المملكة لدى المزودين المرشحين، ومنهم Supabase.

### 3. أدوات المقابلات → `docs/research/interviews/`
- سكربت مقابلة 30 دقيقة لمدير موارد بشرية ومدير فرع، بالعربية.
- نموذج تفريغ موحد يشمل: الألم، والحل الحالي، وتكلفة المشكلة شهريًا، والاستعداد للدفع.
- **إجراء المقابلات مهمة بشرية.** وسمها `Blocked — بانتظار المقابلات`.

### 4. PRD الـ MVP → `docs/prd-mvp.md`
- الشخصيات: موظف فرع، ومدير فرع، وHR، ومالك المنصة.
- لكل وظيفة: user story + معايير قبول بصيغة Given/When/Then + رقم اختبار.
- الحد الأقصى: **ما يُبنى في المرحلة 2 فقط**. وكل ما سواه يذهب إلى `docs/backlog.md` مع تصنيفه.

### 5. السجلات
- `docs/assumptions.md`: كل افتراض، ومستوى ثقته، وكيف يُختبر.
- `docs/risks.md`: المخاطر التقنية والنظامية والتجارية.
- ADR-0001: تأكيد أو تعديل اختيار React Native مقابل Native، بعد التحقق من توفر مكتبات أو وحدات App Attest وDeviceCheck وPlay Integrity وKey Attestation وصيانتها.

## معايير القبول
- [ ] المصفوفة فيها ≥ 10 منافسين، وكل صف له رابط وتاريخ.
- [ ] كل ميزة PARITY لها إما مقابل في الـ MVP أو سبب تأجيل.
- [ ] ksa-requirements خالٍ من أي رقم دون مصدر.
- [ ] PRD لا يحتوي وظيفة خارج نطاق المرحلة 2.
- [ ] ADR-0001 مكتوب.
