# المرحلة 2 — Secure Attendance MVP

اقرأ `CLAUDE.md` و`docs/specs.md` و`docs/prd-mvp.md` و`docs/status.md`.

## الهدف
عميل حقيقي يستطيع: إنشاء فروعه ومواقعه، وإضافة موظفيه، وربط هواتفهم، وتسجيل حضور وانصراف حقيقي، ومراجعة الاستثناءات، وتصدير كشف الحضور.

## النطاق

### Backend
1. **Trust Engine** في `packages/domain`: دوال نقية تطبق specs §A و§B، ومغطاة بـ unit tests لكل فرع في المعادلة.
2. **Attendance API** وفق specs §D: challenges، وpunches، وidempotency (Redis + جدول)، وattendance_events append-only، وattendance_decisions، وlocation_evidence.
3. **Sessions:** بناء الجلسات من الأحداث، ودعم الوردية العابرة لمنتصف الليل، وإغلاق الجلسة المفتوحة تلقائيًا كـ `INCOMPLETE` بعد `max_session_hours` (سياسة).
4. **الورديات الأساسية:** قوالب ثابتة، وتعيين موظف أو مجموعة لموقع ووردية، وفترة سماح للتأخر والخروج المبكر (سياسة).
5. **الاستثناءات والتصحيح:** الموظف يقدم استثناءً على قرار PENDING أو REJECTED، أو طلب تصحيح لبصمة منسية. المدير أو HR يعتمد أو يرفض. التصحيح ينشئ `attendance_adjustments`.
6. **العنوان الوطني:** `NationalAddressAdapter` بواجهة (بحث بالعنوان المختصر → إحداثيات)، وتنفيذ Fake. يكون التنفيذ الحقيقي لسبل `Blocked` حتى توفر الاشتراك. والإدخال اليدوي للإحداثيات على الخريطة متاح دائمًا.
7. **التقارير:** حضور لحظي حسب الفرع، والتأخر والغياب لفترة، والحالات المعلقة. تصدير CSV وXLSX لكشف الحضور الشهري.

### Mobile (Expo)
شاشات: الدخول، ورمز التفعيل وربط الجهاز، والرئيسية (الوردية + حالة الجهاز + حالة الموقع + زر واحد)، ونتيجة البصمة مع السبب والإجراء التالي، والسجل الشخصي، وتقديم استثناء أو تصحيح، وطلب تغيير الجهاز، والإعدادات واللغة.
- وحدات أصلية: App Attest + DeviceCheck على iOS، وKeystore + Key Attestation + Play Integrity على Android.
- جمع 1–3 عينات موقع خلال ≤ 8 ثوانٍ، وإيقاف الجمع فور الوصول إلى دقة ≤ 20م.
- لا يُعرض نجاح قبل رد الخادم. وحالة الشبكة واضحة دائمًا.
- **البصمة دون اتصال خارج نطاق هذه المرحلة.** يعرض التطبيق «لا يوجد اتصال» مع زر إعادة المحاولة.

### Admin Web (Next.js)
للـ HR: الموظفون (إضافة + استيراد CSV مع تقرير أخطاء)، والأجهزة (إصدار رموز التفعيل، وطلبات التغيير، والإيقاف)، والمواقع (خريطة + دائرة أو مضلع + نسخ السياج)، والورديات، والاستثناءات، والتقارير، وسجل التدقيق.
لمدير الفرع: لوحة الوردية الحالية لفروعه فقط، والاستثناءات الخاصة بها.

### Trust Evidence View
صفحة لكل حدث تعرض: القرار، والأسباب، والعينات على الخريطة مع دائرة الدقة، وحالة الجهاز، وسلسلة الموافقات. **دون عرض أي مفاتيح أو tokens.**

## خارج النطاق
الاستراحات، والعمل الإضافي، والموافقات متعددة المستويات، والاشتراكات والفوترة (يُنشأ العميل يدويًا من platform)، والتحقق بالوجه، وأي ذكاء اصطناعي.
