# المرحلة 3 — Workforce Operations

اقرأ `CLAUDE.md` و`docs/specs.md` و`docs/status.md` و`docs/pilot-report.md` (نتائج التجربة).

## شرط البدء
وجود تقرير Pilot يشمل: معدل VERIFIED، ونسبة PENDING وأسبابها، وحالات الرفض الخاطئ، وزمن البصمة الفعلي، وملاحظات HR. **ابدأ بإصلاح أعلى 5 مشكلات فيه قبل أي ميزة جديدة.**

## النطاق
1. **الاستراحات:** مدفوعة وغير مدفوعة، وحد أدنى وأقصى (سياسة)، وتنبيه عند التجاوز.
2. **العمل الإضافي:** احتسابه بعد الساعات المجدولة أو اليومية أو الأسبوعية وفق سياسة بإصدار وتاريخ سريان، مع حالات معتمد وغير معتمد. **لا** حساب أجر إلا بإذن صريح وبيانات أجور مستوردة.
3. **الورديات المتقدمة:** متناوبة، ومقسمة، ومرنة (نافذة حضور)، وتبديل بين موظفين بموافقة، ومناوبات شاغرة، وتنبيه نقص التغطية (المطلوب مقابل الحاضر).
4. **رمضان والعطلات:** تقويم عطلات لكل عميل، وسياسة رمضان تُطبق بتاريخ سريان، وتُطبق حسب إعدادات العميل دون افتراض.
5. **الموافقات متعددة المستويات:** محرك workflow قابل للتهيئة (موظف ← مدير فرع ← HR)، مع تفويض محدد المدة، وتصعيد بعد مهلة.
6. **كشوف الوقت والرواتب:** payroll_periods بحالات OPEN → LOCKED → EXPORTED، وreopen بصلاحية خاصة. تصدير CSV/XLSX عام + **صيغة حماية الأجور / مُدد** وفق ما وُثق في المرحلة 0.
7. **الإجازات (مرجع فقط):** استيراد CSV أو API لأيام الإجازة لكي لا تُحتسب غيابًا. لا طلبات إجازة داخل المنصة.
8. **التكاملات:** API عامة بمفاتيح محدودة النطاق، وWebhooks موقعة (attendance.decided، وexception.resolved، وperiod.locked) مع retry وdead-letter.
9. **SSO:** OIDC لـ Microsoft Entra ID للإدارة.
10. **الاشتراكات (يدوي أولًا):** خطط، وحدود الموظفين النشطين، وعدّاد الاستخدام. الفوترة الآلية مؤجلة.
