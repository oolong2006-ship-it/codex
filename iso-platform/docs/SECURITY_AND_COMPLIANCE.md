## فجوات معروفة (مخططة قبل الإنتاج)
1. MFA للأدوار الحساسة (يتطلب قرار مزود البريد/TOTP) — P1-hardening.
2. RLS على جدول users عبر دالة SECURITY DEFINER لتسجيل الدخول.
3. تحديد معدل على مستوى IP وعلى كل الإجراءات (يتطلب Redis أو جدول) — P5.
4. CSP صارمة (nonce) — P5.
5. فحص المرفقات بمضاد فيروسات وتخزين خاص — مع وحدة الأدلة P3.
6. تشفير الحقول الحساسة على مستوى التطبيق وإدارة الأسرار (KMS) — P5.
7. سياسات الاحتفاظ والحذف وتصدير بيانات المستأجر — P4/P5.
8. اختبار اختراق خارجي — P5.

## PDPL (نظام حماية البيانات الشخصية — السعودية)
- يُطبق على معالجة بيانات أشخاص في المملكة. الاعتبارات: أساس نظامي للمعالجة، إشعار الخصوصية، حقوق أصحاب البيانات، قيود نقل البيانات خارج المملكة، الإبلاغ عن الحوادث.
- **قرار مطلوب (D-02):** موقع الاستضافة. التوصية: منطقة سحابية داخل المملكة لبيانات العملاء السعوديين، وتقييم نقل البيانات إلى مزود AI خارجي (D-06) قبل التفعيل.
- لا تُعد هذه الوثيقة رأياً قانونياً؛ مطلوب مراجعة مستشار مرخّص (D-08).

## ZATCA (الفوترة الإلكترونية)
- عند تفعيل الفوترة: الالتزام بمتطلبات المرحلة المنطبقة على كيان المؤسس (الإصدار والربط والتكامل). ملف PDF ليس فاتورة إلكترونية متوافقة. يُختار مزود فوترة/دفع متوافق (D-03/D-05).

## ادعاءات المنتج
المنصة لا تمنح شهادات ISO ولا تمثل جهة مانحة؛ الشهادة تصدر من جهة مانحة معتمدة بعد تدقيق خارجي. ISO علامة مسجلة للمنظمة الدولية للتقييس.

## الاستجابة للحوادث (مسودة)
اكتشاف → احتواء (إلغاء الجلسات، تعطيل المفاتيح) → تقييم الأثر وتحديد المستأجرين المتأثرين من `tenant_audit_logs` → إبلاغ وفق PDPL → معالجة السبب الجذري → مراجعة لاحقة.
