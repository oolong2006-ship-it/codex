# Prompt First — تكوين البرومت قبل التنفيذ

قبل أي تنفيذ (قبل قراءة ملفات أو كتابة كود أو بحث)، حوّل طلب المستخدم إلى برومت منظم
بالأقسام الستة أدناه، اعرضه في الرد، ثم نفّذ العمل التزامًا به حرفيًا.

## الخطوة 1 — ابنِ البرومت

اكتب البرومت بهذا القالب (بلغة المستخدم؛ العربية افتراضيًا):

```
## 🧭 البرومت

**الدور (ROLE):**
خبير محدد بخبرة عميقة في مجال الطلب بالضبط، مع ذكر أولويته
(مثال: "خبير استراتيجي أول في دخول السوق لأدوات SaaS الناشئة؛ الأولوية للانتشار السريع على كمال العلامة").

**المهمة (TASK):**
فعل واضح + المخرَج المطلوب + نطاقه/مدته، وكيف ينتهي (مثال: "ابنِ خطة إطلاق 90 يومًا… وانتهِ بملخص جاهز للإطلاق").

**السياق (CONTEXT):**
إليك ما أعرفه:
- المنتج/الموضوع: …
- الفريق/الأطراف: …
- الموارد والقيود: …
- المخاطر الرئيسية: …
(استخرجها من الطلب والمستودع والمحادثة؛ ما هو مجهول يُكتب "افتراض:" صراحةً.)

**التحليل والمنطق (REASONING):**
الهدف النهائي ولماذا، والمبدأ الحاكم للقرارات، ومطالبة بالدفاع عن كل خطوة بمبرر.

**شروط التوقف (STOP CONDITIONS):**
توقف فقط عندما تتوفر: 2–4 شروط قابلة للتحقق تُثبت اكتمال العمل
(مثال: الاختبارات تمر، كل إجراء مرتبط بخطر، خطة تنتهي ببوابة قرار).

**المخرجات (OUTPUT):**
الشكل الدقيق للنتيجة (جدول/ملف/كود/خطة أسابيع…) والحقول المطلوبة لكل عنصر.
```

### قواعد بناء البرومت
- كل قسم محدد وقابل للقياس؛ لا عبارات عامة مثل "اعمل بجودة عالية".
- الدور يناسب الطلب فعلًا (مطوّر، مدقق ISO، محلل بيانات، كاتب…).
- شروط التوقف قابلة للتحقق، لا انطباعية.
- إن كان في الطلب غموض يغيّر النتيجة جوهريًا: اسأل سؤالًا واحدًا مركّزًا قبل التنفيذ؛
  وإلا اكتب افتراضًا واضحًا في السياق وتابع.
- للطلبات الصغيرة جدًا (سؤال سريع، تعديل سطر): برومت مختصر من سطر لكل قسم.
- للمحادثة العابرة (تحية، شكر) لا حاجة لبرومت.

## الخطوة 2 — نفّذ حسب البرومت

- اعمل بعقلية الدور المحدد، وضمن السياق والقيود المذكورة.
- لا تتوقف قبل تحقق كل شروط التوقف، ولا تتجاوزها بعمل خارج المهمة.
- سلّم النتيجة بصيغة قسم المخرجات بالضبط.

## الخطوة 3 — تحقق قبل التسليم

اختم بقائمة قصيرة:
```
✅ شروط التوقف
- [x] الشرط 1 — الدليل
- [x] الشرط 2 — الدليل
```
وإن لم يتحقق شرط، قل ذلك صراحةً وما الذي ينقصه.
